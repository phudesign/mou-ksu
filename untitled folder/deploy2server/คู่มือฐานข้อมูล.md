## 1. ภาพรวม

ระบบเก็บข้อมูล 2 ส่วนที่ต้องคู่กัน:

| ส่วน | ที่อยู่ | เก็บอะไร |
|------|---------|----------|
| **MySQL** (`mou_db`) | Pod `mysql` ใน namespace | ผู้ใช้, เอกสาร MOU, กล่องลายเซ็น, audit |
| **ไฟล์ uploads** | Volume ของ Pod `backend` | PDF, รูปลายเซ็น, PDF ที่เซ็นแล้ว |

path ในตาราง (เช่น `pdf_path`) เป็น path **สัมพัทธ์** ใต้ `/app/uploads` ของ backend  
ดังนั้น import SQL อย่างเดียวโดยไม่มีไฟล์ uploads → หน้าเว็บจะหาไฟล์ไม่เจอ

```text
เครื่องพัฒนา                         เซิร์ฟเวอร์ (namespace)
────────────                         ─────────────────────
export-data.sh
  → database/data/mou_db_full.sql  ──import-data.sh──►  MySQL mou_db
  → database/uploads/              ──import-data.sh──►  backend:/app/uploads
```

## 2. ไฟล์และโฟลเดอร์ที่เกี่ยวข้อง

```text
deploy2server/
├── database/
│   ├── schema.sql              โครงสร้างตาราง (CREATE TABLE IF NOT EXISTS)
│   ├── seed.sql                ผู้ใช้ตัวอย่างเล็กน้อย (สำหรับ dev / init)
│   ├── data/
│   │   ├── mou_db_full.sql     dump ข้อมูลเต็ม
│   │   └── EXPORT_INFO.txt     วันเวลา + จำนวนแถวตอน export
│   ├── uploads/                pdfs / signatures / signed
│   └── README.md               สรุปสั้น (ชี้มาคู่มือนี้)
├── k8s/
│   ├── mysql.yaml              Deployment + PVC + Service mysql
│   └── init/
│       ├── 01-schema.sql       คัดลอกจาก schema (ใช้ตอน MySQL สร้างครั้งแรก)
│       └── 02-seed.sql         คัดลอกจาก seed
└── scripts/
    ├── export-data.sh
    ├── import-data.sh
    ├── import-schema-only.sh
    └── backup-db.sh
```

| ไฟล์ | ใช้เมื่อ |
|------|----------|
| `schema.sql` / `k8s/init/01-schema.sql` | สร้างตารางครั้งแรก / เพิ่มตารางใหม่แบบปลอดภัย |
| `seed.sql` | ข้อมูลตัวอย่างเล็กน้อย — **ไม่ใช่ข้อมูล production เต็ม** |
| `data/mou_db_full.sql` | ย้ายข้อมูลเต็มไปเซิร์ฟเวอร์ |
| `uploads/` | ต้องไปพร้อม dump เต็ม |

## 3. การเชื่อมต่อบน Kubernetes / OpenShift

ค่าที่ backend ใช้ (จาก Secret `mou-secrets` + env ใน Deployment):

| ตัวแปร | ค่าปกติบนคลัสเตอร์ |
|--------|-------------------|
| `DB_HOST` | `mysql` (ชื่อ Service) |
| `DB_PORT` | `3306` |
| `DB_USER` | `root` (จาก Secret) |
| `DB_PASS` | จาก Secret `mou-secrets` → `DB_PASS` |
| `DB_NAME` | `mou_db` |

- Service ชนิด **ClusterIP** — เข้าจากนอกคลัสเตอร์ตรงๆ ไม่ได้  
- ข้อมูล MySQL อยู่บน **PVC** `mysql-data`  
- รหัสผ่าน **อย่าใช้ของ dev** (`mou_dev_password`) บนของจริง — ตั้งใน `k8s/secret.yaml`

เข้า shell MySQL จากเครื่องที่มี `kubectl`:

```bash
# ดึงรหัสจาก Secret (หรือใส่เอง)
DB_PASS=$(kubectl -n <NAMESPACE> get secret mou-secrets -o jsonpath='{.data.DB_PASS}' | base64 -d)

kubectl -n <NAMESPACE> exec -it deploy/mysql -- \
  mysql -uroot -p"$DB_PASS" --default-character-set=utf8mb4 mou_db
```

## 4. ตารางใน `mou_db`

| ตาราง | ความหมาย |
|-------|----------|
| `users` | ผู้ใช้ระบบ (login จริงผ่าน LDAP; `username` ต้องตรง LDAP) |
| `user_signatures` | ลายเซ็นที่ผู้ใช้บันทึกไว้ |
| `app_settings` | การตั้งค่าแอป (เช่น `signing_mode`) |
| `mou_documents` | เอกสาร MOU + path ไฟล์ PDF |
| `mou_signature_boxes` | กล่องตำแหน่งเซ็นบนหน้า PDF |
| `mou_signatures` | ลายเซ็นที่ลงในแต่ละกล่องแล้ว |
| `audit_logs` | บันทึกการกระทำ |

Charset: **utf8mb4** / collation **utf8mb4_unicode_ci**

## 5. ตอนขึ้นระบบครั้งแรก

ลำดับที่แนะนำ:

```bash
cd deploy2server
./scripts/build-push.sh
./scripts/deploy.sh          # MySQL ว่าง → ได้ schema+seed จาก init อัตโนมัติ
./scripts/import-data.sh     # ใส่ข้อมูลเต็ม + uploads จากแพ็กเกจ
```

สิ่งที่เกิดตอน `deploy.sh`:

1. สร้าง ConfigMap `mysql-init` จาก `k8s/init/*.sql`
2. Pod MySQL ครั้งแรก (PVC ว่าง) รันไฟล์ใน `/docker-entrypoint-initdb.d`
3. ได้ตาราง + seed เล็กน้อย — **ยังไม่ใช่ dump เต็ม**

จากนั้นต้องรัน `import-data.sh` ถ้าต้องการข้อมูลจากเครื่องพัฒนา

> **หมายเหตุ:** init SQL รันเฉพาะตอน volume MySQL **ว่างครั้งแรก**  
> ถ้า PVC มีข้อมูลอยู่แล้ว การแก้ไฟล์ใน `k8s/init/` จะไม่ถูก apply อัตโนมัติ — ใช้ `import-schema-only.sh` หรือ `import-data.sh` แทน

## 6. Export จากเครื่องพัฒนา

ทำให้ dump ในแพ็กเกจเป็นชุดล่าสุด ก่อนนำไปเซิร์ฟเวอร์:

```bash
# จาก root ของโปรเจกต์ หรือจาก deploy2server
./deploy2server/scripts/export-data.sh
```

สคริปต์จะเลือกแหล่งอัตโนมัติ:

1. ถ้ามี Kubernetes local namespace `mou` และ MySQL รันอยู่ → dump จากที่นั่น  
2. ไม่เช่นนั้น → ใช้ Docker Compose (`db`) ของโปรเจกต์หลัก

ผลลัพธ์:

- `database/data/mou_db_full.sql`
- `database/data/EXPORT_INFO.txt` (เช่น จำนวน users / mou_documents)
- `database/uploads/` (pdfs, signatures, signed)
- อัปเดต `schema.sql` / `seed.sql` และ `k8s/init/` จาก repo หลัก (ถ้ามี)

จากนั้นคัดลอกทั้งโฟลเดอร์ `deploy2server/` ไปเครื่องที่ deploy ได้

## 7. Import เข้าเซิร์ฟเวอร์

**ทับข้อมูลทั้งหมด** ใน `mou_db` ของ namespace นั้น + แทนที่ uploads บน backend

```bash
cd deploy2server
./scripts/import-data.sh
# พิมพ์ yes เพื่อยืนยัน
```

ต้องมีครบ:

- `config.env` (มี `NAMESPACE` ถูกต้อง)
- `database/data/mou_db_full.sql`
- MySQL และ backend ใน namespace พร้อมแล้ว

บน production ที่มีข้อมูลผู้ใช้จริง: **รัน `backup-db.sh` ก่อนเสมอ**

| สถานการณ์ | ใช้คำสั่ง |
|-----------|-----------|
| ย้ายขึ้นครั้งแรก / แทนที่ทั้งก้อนด้วยข้อมูลจากพัฒนา | `import-data.sh` |
| อยากได้แค่ตารางตาม schema ไม่ทับ dump | `import-schema-only.sh` |
| ต้องการ seed เล็กน้อยด้วย | `import-schema-only.sh --with-seed` |

## 8. อัปเดตเฉพาะโครงสร้าง (schema)

```bash
./scripts/import-schema-only.sh
# หรือ
./scripts/import-schema-only.sh --with-seed
```

- `schema.sql` ใช้ `CREATE TABLE IF NOT EXISTS` เป็นหลัก → **ไม่ลบแถวเดิม**
- **ไม่** แก้คอลัมน์เดิมแบบเปลี่ยนชนิด/ลบคอลัมน์ให้อัตโนมัติ  
  ถ้ามีการ migrate ซับซ้อน ต้องเขียน SQL เองแล้ว `kubectl exec ... mysql < migrate.sql`

หลังแก้ `schema.sql` ใน repo หลัก แนะนำรัน `sync-from-repo.sh` หรือ `export-data.sh` เพื่อให้ไฟล์ใน `deploy2server/database` และ `k8s/init` ตรงกัน

## 9. สำรองและกู้คืน

### สำรองจากเซิร์ฟเวอร์

```bash
./scripts/backup-db.sh
# ได้ไฟล์ เช่น deploy2server/backups/mou_db_YYYYMMDD_HHMMSS.sql
```

สำรองเฉพาะ SQL — **ไม่ได้สำรอง uploads**  
ถ้าต้องการไฟล์ด้วย ให้ `kubectl cp` จาก pod backend:

```bash
POD=$(kubectl -n <NAMESPACE> get pod -l app=backend -o jsonpath='{.items[0].metadata.name}')
mkdir -p backups/uploads
kubectl -n <NAMESPACE> cp "${POD}:/app/uploads" backups/uploads -c backend
```

### กู้คืน SQL จาก backup

```bash
DB_PASS=$(kubectl -n <NAMESPACE> get secret mou-secrets -o jsonpath='{.data.DB_PASS}' | base64 -d)

kubectl -n <NAMESPACE> exec -i deploy/mysql -- \
  mysql -uroot -p"$DB_PASS" --default-character-set=utf8mb4 mou_db \
  < backups/mou_db_YYYYMMDD_HHMMSS.sql
```

## 10. ตรวจสุขภาพ / คำสั่งที่ใช้บ่อย

```bash
# Pod / PVC
kubectl -n <NAMESPACE> get pods,pvc -l app=mysql
kubectl -n <NAMESPACE> get deploy mysql

# Log MySQL
kubectl -n <NAMESPACE> logs -l app=mysql --tail=100

# รายการตาราง
kubectl -n <NAMESPACE> exec deploy/mysql -- \
  mysql -uroot -p"$DB_PASS" -e "SHOW TABLES FROM mou_db;"

# นับแถวหลัก
kubectl -n <NAMESPACE> exec deploy/mysql -- \
  mysql -uroot -p"$DB_PASS" -N -e \
  "SELECT 'users',COUNT(*) FROM mou_db.users
   UNION ALL SELECT 'mous',COUNT(*) FROM mou_db.mou_documents
   UNION ALL SELECT 'boxes',COUNT(*) FROM mou_db.mou_signature_boxes;"

# Backend ต่อ DB ได้ไหม (health ยิง SELECT 1)
curl -i https://<โดเมน>/api/health
```

เปรียบเทียบกับตอน export: เปิด `database/data/EXPORT_INFO.txt`

## 11. แก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุที่เป็นไปได้ | วิธีแก้ |
|--------|-------------------|--------|
| `import-data` ไม่พบ `mou_db_full.sql` | ยังไม่ export | รัน `export-data.sh` บนเครื่องพัฒนา |
| เอกสารในเว็บไม่มี PDF | import SQL แล้วแต่ไม่มี uploads | รัน `import-data.sh` ให้ครบ หรือ `kubectl cp` uploads |
| แก้ `k8s/init` แล้วตารางไม่เปลี่ยน | PVC มีข้อมูลแล้ว init ไม่รันซ้ำ | ใช้ `import-schema-only.sh` |
| Login ได้แต่ไม่มี user ในระบบ | LDAP ผ่าน แต่ยังไม่มีแถวใน `users` | เพิ่ม user ในตาราง หรือ import dump ที่มี user นั้น |
| `Access denied` ตอน mysql | รหัสใน Secret ไม่ตรง | ตรวจ `k8s/secret.yaml` / Secret `mou-secrets` |
| MySQL `CrashLoop` / OOM | แรมไม่พอ | ปรับ resources ใน `mysql.yaml` หรือขอโควตาจาก admin |
| ข้อมูลหายหลังลบ PVC | ลบ volume | กู้จาก `backups/` — ป้องกันด้วยอย่าลบ PVC โดยไม่ตั้งใจ |

## สรุปคำสั่งสั้นๆ

| ต้องการ | คำสั่ง |
|---------|--------|
| รีเฟรช dump ในแพ็กเกจ | `./scripts/export-data.sh` |
| ใส่ข้อมูลเต็ม + ไฟล์ขึ้นเซิร์ฟเวอร์ | `./scripts/import-data.sh` |
| แค่ apply โครงสร้างตาราง | `./scripts/import-schema-only.sh` |
| สำรองจากเซิร์ฟเวอร์ | `./scripts/backup-db.sh` |

อย่า commit / อย่าแชร์: `config.env`, `k8s/secret.yaml`, `backups/` ที่มีข้อมูลจริง
